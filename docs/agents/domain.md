# Domain Docs

This repository uses a single domain context. The paths below are relative to the repository root.

## Before exploring

- Read `GLOSSARY.md` for the terms used by the project.
- Read the architectural decision records in `docs/adr/` that apply to the area you are working on.

If a glossary or relevant record is absent, continue without flagging the gap. Create the relevant file through the domain-modeling workflow when a term or architectural decision is settled.

## Use the project vocabulary

Use the glossary's terms in issue titles, proposals, hypotheses, and test names. If a concept has no defined term, first check whether an existing term covers it. Bring a genuine terminology gap to domain modeling.

## Surface conflicts with decisions

If a proposal conflicts with an existing ADR, cite the ADR and explain why the decision might need to be reopened.
